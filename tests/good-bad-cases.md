# Supabase 多用户隔离：Good Case / Bad Case 验收清单

执行前提：已在 Supabase SQL Editor 执行 `db/migrations/0000_init.sql` 至 `0004_supabase_auth_isolation.sql`，并在本机或部署平台配置 Supabase 与数据库环境变量。

## Good Case（必须通过）

| 编号 | 操作 | 预期结果 |
| --- | --- | --- |
| G-01 | 用户 A 注册、确认邮箱、登录 | 进入空的个人经历库；侧栏显示 A 的用户名或邮箱。 |
| G-02 | A 上传 PDF/DOCX/TXT/Markdown（≤20MB） | 文件上传至私有 `experience-materials/A-user-id/...`；AI 能继续解析和生成候选经历。 |
| G-03 | A 保存经历、简历资料、生成简历草稿 | 每条写入的 `user_id` 均为 A 的 Supabase Auth UUID；刷新后只能看到 A 的资料。 |
| G-04 | 用户 B 用另一浏览器/无痕窗口注册登录 | B 的经历库、简历资料和“我的简历”均为空，不显示 A 的任何内容。 |
| G-05 | B 上传自己的材料并生成草稿 | B 的文件、经历、简历都能独立显示；A 刷新后仍只看到 A 的数据。 |
| G-06 | A 点击自己的来源材料 | `/api/files/<A-file-id>` 返回文件并允许预览/下载。 |
| G-07 | A 使用“忘记密码” | 收到 Supabase 重置邮件；打开邮件链接后可设置新密码；旧密码无法登录。 |
| G-08 | A 点击退出登录 | 再访问业务 API 返回 401；页面回到登录页。 |

## Bad Case（必须被拒绝或安全降级）

| 编号 | 尝试 | 预期安全结果 |
| --- | --- | --- |
| B-01 | 未登录直接请求 `/api/library`、`/api/resumes` 或 `/api/process` | `401`，不返回任何个人数据。 |
| B-02 | B 把地址栏改为 `/api/files/<A-file-id>` | `404`，不泄露该文件是否真实存在。 |
| B-03 | B 在请求体中伪造 `user_id: A` | 接口忽略请求中的 `user_id`；所有写入仍使用登录会话中的 B UUID。 |
| B-04 | B 使用 Supabase Storage API 访问 `experience-materials/A-user-id/...` | Storage RLS 拒绝访问；对象路径不提供公开 URL。 |
| B-05 | 未设置 `NEXT_PUBLIC_SUPABASE_URL` 或 anon key | 页面只显示“需要连接 Supabase”，不会回退到共享 `local-user` 数据。 |
| B-06 | `DATABASE_URL` 未配置 | 已登录用户收到 `503` 配置提示；不会写入本地文件或半完成业务数据。 |
| B-07 | 上传 >20MB、格式不受支持或涉密材料 | 前端/后端拒绝；涉密提示持续显示。具体格式白名单以上传接口为准。 |
| B-08 | 删除或篡改浏览器 Cookie | 后端 `supabase.auth.getUser()` 校验失败，返回 `401`。 |

## 真实环境回归步骤

1. 用 A、B 两个独立浏览器会话分别完成 G-01 至 G-05。
2. 在 B 会话依次执行 B-01 至 B-04；记录 HTTP 状态码和页面行为。
3. 在 Supabase Table Editor 抽查业务表：每行的 `user_id` 必须等于创建者的 `auth.users.id`。
4. 在 Supabase Storage 页面确认 bucket 为 Private，且对象按用户 UUID 目录分隔。
5. 运行 `npm test`、`npm run lint`、`npm run build`；再重复一次 G-02 和 G-05，检查回归。

## 英文简历输出回归

| 编号 | 操作 | 预期结果 |
| --- | --- | --- |
| E-01 | 选择“英文”并完成生成 | 生成一份标记为“英文”的独立草稿；预览和 Word 中的固定区块为 Education、Work Experience、Internship Experience、Project Experience、Campus Experience、Skills。 |
| E-02 | 英文草稿中选择“保持原文”的经历 | AI 只忠实翻译已确认内容，不新增职责、数字、工具或成果。 |
| E-03 | 选择“中英文双份” | 依次生成并保存一份中文草稿和一份英文草稿；“我的简历”可分别打开和下载。 |
| E-04 | 使用包含中文学校名、技能或证书的简历资料生成英文版 | 保留用户填写的原值，不猜测官方英文名称；如需标准英文名，用户可在简历资料中先改为希望展示的形式。 |
| E-05 | 英文简历使用中文姓名、学校和专业 | 姓名显示为“中文姓名 / ENGLISH NAME”；学校与专业显示为对应的自然英文。网页预览与下载 Word 使用同一份英文资料快照。 |

## JD 图片、修改稿版本与双语简历回归

| 编号 | 操作 | 预期结果 |
| --- | --- | --- |
| R-01 | 在主 JD 文本框粘贴 PNG/JPG/WEBP 图片 | 只在当前浏览器生成预览；显示蓝色圆角实心按钮“点击提取文字”，不显示“图片只会在当前浏览器中处理，不会保存”的冗余提示。 |
| R-02 | 点击主 JD 图片的“点击提取文字” | 按钮显示“正在提取…”及进度；成功后把文字追加到主 JD 输入框，并变为“重新提取文字”。 |
| R-03 | 在参考 JD 中粘贴图片，且页面存在多个参考 JD | “点击提取文字/重新提取文字”与删除参考 JD 的 × 分开排布，不遮挡、不重叠；各图片文字只追加到所属参考 JD。 |
| R-04 | 第四步点击“自己编辑” | 编辑框默认载入结构化的原始经历（摘要和证据点），而不是 AI 修改稿。 |
| R-05 | 第四步点击“基于AI修改稿”，再点击“基于原文” | 编辑框分别切换为 STAR 修改 bullets 和原始版本；保存编辑后，仅本次简历使用该手工版本，不覆盖经历库。 |
| R-06 | 在第四步完成所有经历确认后点击“AI生成中文简历” | 生成、保存并预览一份中文草稿；可下载中文 Word。 |
| R-07 | 点击“AI生成英文简历” | 用英文提示词生成、保存并预览一份英文草稿；固定模块标题及 AI 面向招聘者字段为英文；可下载英文 Word。 |
| R-08 | 点击“AI生成中英文简历” | 依次生成两份独立草稿；第五步上方是中文、下方是英文，且有两个独立 Word 下载按钮。 |
| R-09 | 查看网页预览或下载 Word | 每条经历 bullet 使用两端对齐；经历按工作、实习、项目、校园分区，各分区内按时间从近到远排列。 |
| R-10 | 进入“我的简历”并打开任意历史草稿 | 可重新打开对应草稿并下载其对应语言的 Word，不会错误展示其他草稿。 |
| R-11 | 第四、五步调用 AI | 请求只发送选中经历的 `id/title/org/period/type/summary/tags/evidence` 及用户确认的本次文本；不发送附件 URL、来源材料或 `source_chunks` 原文。 |

## 本轮 Bad Case（必须被阻止或明确提示）

| 编号 | 尝试 | 预期结果 |
| --- | --- | --- |
| RB-01 | 粘贴非 PNG/JPG/WEBP 图片或单张超过 10MB | 图片不会加入 JD 列表，并提示格式或大小限制。 |
| RB-02 | OCR 正在运行时重复点击提取 | 提取按钮禁用并显示“正在提取…”，不发起并行的同一图片识别任务。 |
| RB-03 | OCR 无法识别文字 | 显示该图片的可读错误提示，保留图片以便用户重新提取或移除，不污染 JD 输入框。 |
| RB-04 | 未选择经历、未完成 AI 修改稿确认或仍打开编辑框时生成简历 | 不生成草稿，提示先选择经历并逐段确认“采用 AI 修改稿 / 自己编辑 / 保持原文”。 |
| RB-05 | 点击“基于AI修改稿”但该段 AI 未返回 bullets | 不覆盖编辑框，提示“AI尚未生成可采用的修改稿”。 |
| RB-06 | 经历对象未来新增附件、源文件或来源材料字段 | `toResumeAiInput` 白名单投影仍会把它们排除在两个 AI 接口之外，避免 token 膨胀或上传原文。 |
